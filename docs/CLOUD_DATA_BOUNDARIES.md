# ReMind 云端服务契约与数据边界

> 版本：V1 草案  
> 日期：2026-07-29  
> 对应进度：云端改造阶段 1

## 1. 设计目的

App 只依赖 ReMind 的稳定服务契约，不直接依赖腾讯云、阿里云、Cloudflare、某个模型供应商或某种数据库。

当前本地服务继续使用 `/api/...`。云端服务使用 `/api/v1/...`。两者在 App 内通过同一个服务配置和请求入口访问，迁移期间不得要求用户重新配对当前本地微信。

## 2. 服务模式

| 模式 | 标识 | 身份方式 | 数据位置 | AI 费用 |
| --- | --- | --- | --- | --- |
| 自助部署 | `self-hosted` | 现有设备凭据 | 用户的 Mac、本地 D1 和手机 SQLite | 用户自付 |
| 云端托管 | `hosted` | 用户会话加设备凭据 | 云端用户空间和手机本地缓存 | 关闭、自带 Key 或托管额度 |

没有显式配置模式时，App 必须默认使用 `self-hosted` 和旧版 `/api` 路由，以保证当前 1.0.2 行为不变。

## 3. API 版本边界

- 当前本地接口：`/api/devices/...`
- 云端 V1 接口：`/api/v1/...`
- App 业务界面不得自行拼接完整接口地址。
- API 地址和版本是公开配置，不得包含密钥。
- 用户会话、设备密钥和 API Key 只允许通过请求头发送。
- 服务端响应不得返回其他用户的内部 ID、文件路径或密钥信息。

云端 V1 的计划资源：

```text
/api/v1/session
/api/v1/users/me
/api/v1/devices
/api/v1/wechat-connections
/api/v1/notes
/api/v1/jobs
/api/v1/files
/api/v1/ai-credentials
/api/v1/billing/account
/api/v1/billing/ledger
```

## 4. 数据所属关系

云端所有私有实体必须能追溯到唯一用户。

```text
user
 ├── devices
 ├── wechat_connections
 ├── notes
 ├── jobs
 ├── files
 ├── api_credentials
 └── billing_account
      └── ledger_entries
```

### `users`

- 云端账号的唯一所有者。
- 禁止使用微信 `open_id` 直接代替 ReMind 用户 ID。
- 删除账号时进入可审计的异步清理流程。

### `devices`

- 必须包含 `user_id`。
- 设备密钥只保存哈希；服务端不能还原原始设备密钥。
- 用户可以查看并撤销自己的设备。

### `recovery_credentials` 与 `user_sessions`

- 私密测试阶段采用设备优先的匿名账号，不依赖短信或邮箱。
- 恢复码只向用户展示原始值一次，数据库只保存规范化后的哈希。
- 恢复码用于给同一账号增加新设备，不直接作为日常 API 会话令牌。
- 会话必须同时属于用户与设备，设备撤销后对应会话立即失效。
- 会话令牌只保存哈希并设置明确的过期时间。

### `wechat_connections`

- 必须包含 `user_id`。
- 微信令牌使用密钥托管层加密，普通业务查询不得返回明文。
- 一个微信连接不能同时归属于两个用户。

### `notes`

- 必须包含 `user_id`。
- App 本地 SQLite 仍是离线可用的数据副本；云端同步使用独立的同步版本和删除标记。
- 云端 ID 与本地 ID 不依赖数据库自增值，避免迁移和离线冲突。

### `jobs`

- 必须包含 `user_id`、任务类型、幂等键、状态和费用预占记录。
- Worker 领取任务后仍要使用 `user_id` 约束读取笔记、文件和密钥。
- 重试不得造成重复 AI 调用、重复记账或重复笔记。

### `files`

- 必须包含 `user_id`、对象存储键、大小、类型、过期时间和内容哈希。
- 对象存储键带不可猜测 ID，但不能只依赖路径实现权限控制。
- 下载必须使用短时授权地址，日志不得记录完整签名参数。

### `api_credentials`

- 必须包含 `user_id`、供应商、加密版本和密文。
- 不保存可检索的明文 Key。
- 默认 API 响应只返回是否配置、供应商和末尾掩码。
- 删除凭据后，不允许已有排队任务继续读取该 Key。

### `billing_accounts` 与 `ledger_entries`

- 余额账户必须包含 `user_id`。
- 账本记录只追加，不直接修改或删除历史金额。
- 每次预占、结算、释放、充值和退款都有唯一幂等键。
- 可用余额由已确认账本计算或由受事务保护的快照加账本校验得到。

## 5. 授权规则

每个云端请求至少经过以下检查：

1. 验证用户会话；
2. 验证当前设备未被撤销；
3. 从会话确定 `user_id`，不采信客户端传入的 `user_id`；
4. 查询和修改时同时使用资源 ID 与 `user_id`；
5. Worker 执行任务时沿用任务所属用户，不能获得全库默认访问权限；
6. 管理操作使用独立后台身份并留下审计记录。

## 6. 密钥边界

- `EXPO_PUBLIC_*` 只用于服务地址、模式和 API 版本等公开配置。
- App 的用户会话与设备密钥保存在 Expo SecureStore。
- 恢复码不能只保存在 SecureStore；必须提示用户另行保存，因为 Android 卸载 App 会清除 SecureStore 数据。
- 用户 API Key 上传成功后，App 可以不再保留完整 Key。
- 服务端业务数据库只保存密文和密钥版本。
- 解密只发生在模型请求前的最短时间内，解密值不进入队列载荷和日志。
- 平台托管 Key 永远不进入 App 安装包。

## 7. 当前兼容性决定

- 旧版未配置 `EXPO_PUBLIC_REMIND_API_VERSION` 时继续请求 `/api`。
- 旧版设备凭据的 SecureStore 作用域保持原来的 API 地址，现有微信配对不会失效。
- 只有显式设置 V1 路由时才使用新的凭据作用域和 `/api/v1`。
- 本阶段不修改 `remind.db` schema，不搬迁现有数据，不启用云端账号。
