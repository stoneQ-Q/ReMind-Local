## 1. 当前结论

这不是一个 Web 产品，而是一个以手机为主要入口的个人 AI 笔记 App。

产品名统一为 **ReMind**。当前代码和真机原型已经跑通：

```text
微信发送内容
  → 独立微信网关接收
  → Cloudflare Worker / D1 暂存
  → Android App 同步到本地 SQLite
  → DeepSeek 生成可审核笔记
  → 用户确认
  → 精选同步到 Obsidian
```

关联对话进一步明确了 ReMind 的长期产品方向：

> 把视频、播客、图片、文章或文字交给它，自动提炼重点、保留来源，
> 并让知识持续长进用户自己的笔记里。

当前版本已经形成低压力捕获闭环，下一阶段将 ReMind 扩展为多模态、可追溯、
持续生长的个人知识工具。

## 2. 已实现能力

### 手机 App

- Expo 54、React Native、TypeScript；Expo Go 已在 Android 真机验证，
  EAS `preview` 配置可生成不依赖 Metro 的可安装 APK。
- SQLite 本地优先，数据库版本 `16`；v16 是不落地媒体文件的空迁移版本，
  用于保持已经发到真机热更新路径上的版本号单调递增。
- 首页快速记录、最近记录、全文搜索、编辑、软删除。
- 分类筛选：全部、ReMind、微信、整理笔记、链接。
- 数据维度已经拆分：
  - `record_type`：原始记录或 AI 整理笔记。
  - `source`：App、微信、分享、AI。
  - `content_kind`：文字、链接，并为图片、音频、文件、混合内容预留。
- 深链快速记录和来源去重。
- AI 整理稿审核、修改、接受或丢弃。
- 链接笔记必须先有用户自己的保存意图，不能只丢一个 URL。
- 链接整理稿现在会生成正式 `source` 来源笔记：
  - Worker 先把网页正文切成带稳定 ID 的原文证据块。
  - DeepSeek 只选择证据 ID，Worker 再取回逐字引用并保留字符位置，
    避免模型轻微改写标点或空白导致整篇失败。
  - 审核页分开展示用户保存意图、AI 整理结果与原始证据。
  - 接受后，保存意图、证据片段和原文链接进入普通 Markdown。
- 来源笔记接受后可以继续生成可审核的主题 patch：
  - 建议补充已有主题，或新建一篇 `theme` 主题笔记。
  - 用户可查看理由、局部 Markdown patch 和潜在冲突。
  - 审核页同时列出已有主题与“新建主题”，用户可以覆盖 AI 的单次判断。
  - 模型提示优先将较窄来源补进能够容纳它的已有宽主题。
  - 模型必须逐个评估已有主题并返回 0–100 匹配分；Worker 使用可信阈值
    自动召回最匹配主题，所有候选都明显不相关时才允许新建。
  - 匹配拆为主要研究对象、长期用途和新增贡献；研究对象不一致时，
    “深度阅读”等宽泛方法主题不能吸收具体文学、技术或健康内容。
  - 只有确认后才更新主题笔记；来源笔记始终独立保留。
  - `theme_sources` 防止同一来源被重复合并。
  - SQLite v12 在 `theme_sources` 保存每篇来源实际加入主题的 Markdown 段落；
    来源详情可查看当前主题，并把该段落原子移动到已有主题或用户命名的新主题。
    原始微信文章详情会沿引用关系找到对应来源笔记，展示同一个归类入口。
  - 主题标题和正文均可在笔记页直接编辑；同步继续使用稳定 `remind_id`，
    不会因改名创建重复的 Obsidian 记录。
  - SQLite v13 不再把“由重新归类来源创建”作为主题摘要，已有同类摘要会
    无损清空，使首页卡片直接显示主题正文的首段。
  - 主题详情默认按 `theme_sources.contribution` 呈现来源卡片，而不是直接
    展示不断增长的拼接 Markdown。卡片默认折叠，可展开阅读、打开原文或
    重新归类；右上角“编辑”仍保留完整 Markdown 编辑能力。
  - 来源卡片的“查看整理笔记”会在主题页上方打开完整来源笔记，关闭后回到
    原主题位置；“打开原文”仍直接指向可追溯网页。
  - 首页主题卡片显示“来源数量 + 最近补充时间”，降低长期积累后的视觉噪音。
  - SQLite v14 新增独立 `theme_overviews`，主题主页顶部展示可编辑的“当前理解”。
    新来源审核会分开显示来源贡献和更新后的完整概览，用户确认后才一起写入。
  - 如果用户在审核时改选了其他主题，只移动来源贡献，不使用针对原候选生成的
    概览。主题概览也会写入同一个 Obsidian Markdown 并参与指纹同步。
- 首页默认使用“收件箱”视图，隐藏已经生成来源笔记的原始链接捕获；
  “全部”仍可查看完整记录。最近内容按今天、昨天和更早分组。
- 首页卡片优先显示摘要，并将 Markdown 标题、列表、引用、强调与链接语法
  转换为纯文本缩略内容。
- UI 品牌统一为 “ReMind”：奶油白背景搭配灰绿、雾蓝、淡杏和浅紫纸卡；
  首页记录框使用克制的错位双线与别针元素，标题使用宋体阅读层级。
- 首页使用单一 `SectionList`：品牌、快速记录框、标题和分类作为列表头部，
  向下阅读时共同滚出；日期分组不吸顶，底部导航保持固定。
- 首页卡片摘要限制为两行；点击已选中的“记录”标签会回到顶部并聚焦输入框。
- 用户可见文案避免反复强调 DeepSeek/AI，改为“整理稿”“整理后的笔记”等
  个人笔记语气；技术配置和稳定的 `ReMind/Inbox` 路径保持不变。
- Markdown 原文保持不变；审核页和正式笔记详情使用格式化阅读模式，
  仍可切换到 Markdown 编辑。

### DeepSeek 整理

- 模型调用放在 Worker，API Key 不进入 App。
- 当前模型：`deepseek-v4-flash`。
- 支持“整理今天”，最多生成 3 篇可审核草稿。
- 支持单链接整理：
  - 用户保存意图。
  - 页面标题、站点和正文。
  - 内容概括、关键观点、与用户的关系、可选行动项、原始来源。
- AI 失败不删除原始记录，失败链接可以重试。
- 服务端校验 DeepSeek JSON、来源 ID、字段长度和输出数量。
- 链接证据 ID 若不属于本次网页正文，整个整理结果会被拒绝并允许重试，
  不会把无法追溯的观点写成本地正式笔记。

### 微信入口

- 不要求最终用户安装 OpenClaw。
- 使用独立 `gateway/` 进程接入腾讯微信 iLink / ClawBot 协议。
- App 生成 6 位配对码，网关和设备绑定。
- 支持微信文字与链接记录。
- 链接支持两种输入：
  - 一条消息中发送“链接 + 保存意图”。
  - 先发链接，再补一句描述。
- 微信确认回复支持：首次回复、每次回复、完全静默。
- 微信公众号文章由本地网关抓取正文，再上传 24,000 字符以内的页面快照。
  这是为了绕过 Cloudflare Worker 直接访问公众号文章时遇到的验证页。
- App 未携带快照时，Worker 会按“设备 + URL”读取服务端已存快照兜底。
- 小红书图文链接已有独立适配器：
  - 网关使用桌面浏览器身份跟随短链，并提取标题、作者文案和配图。
  - 已用真实分享链接验证 8 张配图和约 300 字作者文案。
  - 配图优先交给智谱收费模型 `glm-4.6v` 生成图片观察，调用失败时降级到免费
    `glm-4.6v-flash`；DeepSeek 继续负责结合保存意图、作者文案和视觉观察
    整理笔记。
  - 图片观察单独保存和展示，不能进入逐字网页证据，避免模型观察冒充原文。
  - App、SQLite 和 Obsidian 不保存配图文件，只保存识图后整理出的重点文字与
    原始链接；需要查看画面时回到来源页面。
  - 多模态来源笔记已改为自然的“内容概括 / 值得留下的内容 / 与我的关注点”；
    画面与作者文案重复时不再复述，只有新增信息才生成最多 3 条“画面补充”。
  - Worker 会把模型使用的证据块 ID（如 `E1`）转换成用户可读的引用序号
    `〔证据 1〕`。
- 小红书视频链接已完成音频优先摄取：
  - 网关从页面识别视频和时长，视频直链只在当前处理任务中使用，不上传 D1。
  - FFmpeg 在系统临时目录中把音轨切成 28 秒、单声道、16 kHz 的低码率 MP3；
    默认先由本机 MLX Whisper 转写；本地模型不可用或转写失败时，再通过已配对
    连接器调用 Worker 的 `glm-asr-2512`。
  - 成功和失败都会删除临时目录；App、SQLite、D1 和 Obsidian 都不保存视频或
    音频文件，只保存作者文案、带时间戳转写和原始链接。
  - 视频处理在网关串行后台队列中运行，不阻塞微信继续收件；网关重启后会查询
    D1 中 pending / failed 的链接继续处理。
  - 已用真实 264 秒小红书视频验证本地 Whisper：10 段、2147 个字符，约 19 秒
    完成，云端 ASR 费用为 0，临时目录已清理。
  - 视觉模型不再默认理解整段视频；只有语音无法说明、且用户确实关注画面信息时
    才应增加按需视觉采样。
  - 网关通过统一 `TranscriptionProvider` 边界实现
    `local-whisper → zhipu-cloud` 自动兜底，不改视频切片、时间戳合并、快照
    和笔记生成流程。
- 视频任务会逐段上报进度、转写提供方和按公开单价估算的费用；首页快速记录区
    下方显示“正在转写 3/14”。失败任务不会无限自动重试，用户可在同一卡片
    手动重试，网关会在 15 秒轮询内接手。
  - 云端 ASR 默认费用上限为 ¥0.30，可通过
    `REMIND_CLOUD_ASR_LIMIT_YUAN` 调整。本地 Whisper 不产生云端费用；只有本地
    不可用或失败且云端估价超过上限时，任务才进入 `awaiting_approval`，等待
    用户在 App 点击“继续整理”，确认前不会调用云端 ASR。
- 本地服务稳定性已封板：
  - `server/scripts/dev-local.mjs` 在启动前从 macOS 钥匙串读取三项凭据，并检查
    DeepSeek 认证、本地 Whisper 模型和必要配置；自检失败时不会启动 Worker，
    避免任务进入必然失败状态。
  - DeepSeek 的认证失败、限流、超时、内容校验失败和来源读取失败使用不同错误码；
    401 / 403 不再无意义地重复请求。
  - 失败来源再次生成时复用 SQLite / D1 中已有页面快照和视频转写，不重新下载或
    转写；详情页明确说明“已有视频转写已保留”。
  - 微信设置页显示网关、笔记整理、本地 Whisper 和图片理解的运行状态。网关每
    15 秒上报一次能力与心跳。
  - Worker 与微信网关已安装为当前用户的 macOS LaunchAgent：
    `app.remind.worker` 和 `app.remind.gateway`。Mac 登录后自动启动，
    异常退出会自动恢复，日志写入 `~/.remind/logs`。
  - 已通过 `SIGKILL` 验证两个进程均由 `launchd` 重新拉起，本地
    `http://127.0.0.1:8787/health` 恢复正常；运行不再依赖 Codex 终端会话。

## 5. 本地运行与敏感配置

### App

根目录 `.env.local` 当前指向：

```text
EXPO_PUBLIC_REMIND_API_URL=http://192.168.31.122:8787
```

电脑局域网 IP 变化后必须同步修改。启动：

```bash
npm start
```

### Worker

本地调试必须监听局域网，否则手机无法访问。`server/package.json` 已固定：

```bash
npm run dev
```

等价于：

```bash
wrangler dev --ip 0.0.0.0
```

本地还需要私密的 `WECHAT_TOKEN`、`DEEPSEEK_API_KEY` 和 `ZHIPU_API_KEY`。
当前机器已把三项凭据存入 macOS 钥匙串，账户名为 `remind-local`；仓库中不保存
明文密钥。`npm run dev` 会读取钥匙串、完成自检，再通过权限为 `0600` 的运行期
临时 env 启动 Wrangler，退出时自动删除临时目录。单独检查：

```bash
cd server
npm run service:check
```

### 微信网关

```bash
cd gateway
npm start
```

登录和连接器配置保存在：

```text
~/.remind-weixin/config.json
```

文件包含凭据，权限应保持 `0600`，不得提交。当前网关仍运行在个人电脑，
尚未云化。本机优先转写依赖：

```text
~/.remind-weixin/whisper-venv/bin/mlx_whisper
~/.remind-weixin/models/whisper-small-mlx-4bit/config.json
```

也可分别用 `REMIND_MLX_WHISPER_PATH` 和 `REMIND_WHISPER_MODEL_PATH` 指向其他
CLI 与模型目录。缺少任一项时网关会自动使用智谱兜底。

## 6. 关联对话确定的长期产品方向

关联对话不是要增加社交，而是把 ReMind 提升成个人 AI 笔记工具。

### 明确保留

- 手机端低压力输入。
- 视频、播客、语音、图片、长文本、网页链接的统一摄取。
- AI 生成的是可编辑初稿，最终仍是用户自己的普通笔记。
- 重要观点必须回到原始证据：
  - 网页原始段落。
  - 视频画面和时间戳。
  - 播客音频位置。
  - 图片区域。
  - PDF 页码。
- 标准 Markdown 与 Obsidian 开放出口。
- 待办提取、周记、月章、关联记忆和个人笔记问答作为后续智能能力。

### 明确排除

- 社交广场、公开社区和 MindBack 的「站点」模式。
- 把 AI 摘要本身当作最终产品。
- 在 Expo 客户端运行 Python、FFmpeg、Whisper 或视频下载逻辑。
- 每保存一个来源就制造一张永远不再使用的“摘要卡片”。

### 最重要的差异化

```text
中文内容摄取能力
  × 可追溯的来源笔记
  × 持续生长的主题笔记
  × 逐渐学习用户的整理偏好
```

建议采用两层笔记：

1. **来源笔记**：忠实整理一条文章、视频、播客或图片，保留证据位置。
2. **主题笔记**：多个来源不断补充同一个长期主题；每次更新都可审核，
   展示新增、支持、冲突和来源。

产品真正的承诺应是：

> 每一次投入，都让已有笔记变得更完整，而不是让摘要列表变得更长。

- Slogan：`remember what matters`

## 9. 当前遗留与风险

- Expo 原生 Share Extension / Android Share Intent 尚未真正接入。
- 微信网关依赖个人电脑长轮询，其他用户无法直接规模化使用。
- 还没有账户、跨设备同步、权限隔离和生产级限流。
- 公众号正文提取依赖非官方页面结构，需要失败重试和备用提取器。
- Markdown renderer 是轻量自研，只覆盖常用标题、列表、引用、加粗、代码
  和 HTTP 链接，不是完整 CommonMark。
- 视频已有网关内串行队列和 D1 pending 恢复，但还没有正式 job 表、分段进度、
  重试次数和指数退避。
- 来源引用目前以整页来源为主，还没有段落级锚点。
- `ReMindApp.tsx` 体积已经很大，下一阶段应按 capture、notes、review、
  settings 拆分。
- 当前 Git 仓库没有基线提交，工作区文件全部显示为未跟踪。继续大改前应
  审核 `.gitignore`、排除密钥和临时产物，然后建立可回退的初始基线。
