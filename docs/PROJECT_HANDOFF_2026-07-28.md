## 1. 下一位开发者先知道这些

ReMind 是移动端优先、本地优先的个人知识 App，不是 Web 产品，也不是单纯的
AI 摘要工具。

当前真实闭环：

```text
微信捕获
  → 本机微信网关读取公众号、小红书图文或视频
  → 本地 Cloudflare Worker / D1 处理
  → Android App 拉取并写入 remind.db
  → DeepSeek 生成可审核来源笔记
  → 用户确认并归入长期主题
  → 相关记忆与主动回想
  → 精选同步到 Obsidian
```

最重要的产品原则：

> 每一次投入，都让已有笔记变得更完整，而不是让摘要列表变得更长。

不要重新初始化项目，不要清除 SQLite、SecureStore、D1、微信网关登录、
微信配对或 Obsidian 数据。

## 4. 已完成的主要能力

### App 与本地数据

- Expo 54、React Native 0.81、TypeScript。
- SQLite schema version `16`，v16 是保持版本单调的空迁移。
- 快速记录、搜索、编辑、软删除、最近删除恢复。
- 收件箱、来源、微信、链接、整理笔记和主题分类。
- Markdown 阅读渲染与纯文本卡片摘要。
- JSON 数据导出与合并导入。
- 首页单一滚动流和低饱和纸卡视觉。

### AI 与来源追溯

- “整理今天”和单链接可审核草稿。
- 用户保存意图是链接整理的必要输入。
- Worker 对模型 JSON、来源 ID 和字段长度做校验。
- 网页先切成证据块，模型只选 ID，Worker 取回逐字原文和字符位置。
- 原始捕获、页面快照和用户保存意图在 AI 失败时保留。
- 接受正式来源笔记后，原始链接自动从普通列表归档但不删除。

### 长期主题与找回

- 自动评价已有主题并建议补充或新建。
- 用户可以覆盖模型判断或自己命名新主题。
- 每个来源只有一个主题归属。
- 主题使用局部 patch，不整篇重写。
- 主题主页分离“当前理解”和来源贡献卡片。
- 来源可重新归类，并保留安全删除边界。
- 来源详情展示最多三条相关记忆。
- 首页每天最多一条“最近值得再看”。

### 微信、图文与视频

- 微信 iLink / ClawBot 长轮询接入。
- 文字、公众号、普通网页、小红书分享文本进入 ReMind。
- 小红书图文提取标题、作者文案和配图；智谱视觉模型生成独立图片观察。
- 来源媒体不复制进 App、SQLite、D1 或 Obsidian。
- 小红书视频音频优先：
  - FFmpeg 临时切片；
  - 本机 MLX Whisper 优先；
  - 智谱 ASR 自动兜底；
  - 带时间位置的转写；
  - 处理结束强制清理临时媒体。
- 网关后台串行队列、D1 pending 恢复和 App 分段进度。
- 云端 ASR 默认费用上限 ¥0.30，超限先等用户确认。

### Obsidian

- Android 授权 Vault 并写入 `ReMind/Inbox`。
- 使用稳定 `remind_id`、内容 hash 和同步状态。
- 来源证据、链接和主题当前理解进入普通 Markdown。
- 单向同步，不自动把 Obsidian 修改回写 ReMind。
- 删除 ReMind 笔记不直接删除 Obsidian 文件。

### 独立运行

- EAS preview APK 已跑通。
- 关闭 Codex、终端和 Metro 后，安装版仍可运行。
- Worker 和网关由 `launchd` 自动启动和异常恢复。
- API 密钥存入 macOS 钥匙串，项目不保存明文。

## 6. 运行配置

```text
EXPO_PUBLIC_REMIND_API_URL=http://192.168.31.122:8787
```

手机与 Mac 必须处于同一局域网；Mac IP 变化后当前安装包无法访问 Worker。

```text

```


只有再次迁移旧 Expo Go 数据时才使用该环境变量；独立版不要设置它。

## 8. 微信配对的重要细节

当前 `gateway/src/index.ts` 的 CLI 默认 API 是已部署 Worker：

```text
https://remind-wechat.chartreuse-canvas.workers.dev
```

但 `1.0.2` 安装包使用本机 Worker。手动配对本机六位码时必须显式指定：

```bash
cd /Users/stone/Documents/remind/gateway
REMIND_API_URL=http://127.0.0.1:8787 npx tsx src/index.ts pair <六位码>
cd ..
npm run services:restart
```

否则配对请求可能访问远端 Worker 并超时。成功后
`~/.remind-weixin/config.json` 会保存本地 API 地址，常驻网关继续使用该配置。

下一版本应消除这段人工流程。

### 10.2 捕获入口

- [既定] App 随手记、微信、系统分享和深链保持同一个低压力收件箱。
- [既定] 所有内容先保存，再异步理解；AI 和网络不能成为记录的单点故障。
- [既定] 支持文字、网页、图片、语音、视频、播客、PDF 和文件。
- [建议] 增加拍照扫描、系统相册选择和文件选择。
- [建议] 语音随手记录音结束后先保存音频状态，再异步转写；用户确认后可选择

- [建议] 对一条捕获允许补充“为什么保存”“希望以后怎么用”和目标主题，
  但这些都不应阻塞快速记录。
- [建议] 收件箱支持批量补意图、批量归档、批量删除和稍后整理。
- [建议] 增加重复来源提示：同一个链接再次出现时，优先提示已有笔记和新增意图，
  不简单制造重复卡片。

### 10.3 多模态摄取与来源证据

- [既定] 网页保留逐字段落证据和原始链接。
- [既定] 视频、播客和语音保留时间戳。
- [既定] PDF 保留页码；图片证据应能指向对应图片或区域。
- [既定] Python、FFmpeg、Whisper、下载器和 OCR 继续运行在服务端或独立网关，
  不进入 Expo 客户端。
- [建议] 普通网页补充作者、发布日期、抓取时间和站点信息。
- [建议] PDF 使用文本层优先、OCR 兜底，并记录“文本层 / OCR”的证据来源。
- [建议] 长视频先做章节和语音转写；只有保存意图需要画面事实时才按需抽帧。
- [建议] 播客支持 RSS 单集链接、章节、说话人和时间位置。
- [建议] 外部视频平台采用独立适配器和后台任务边界，参考 BiliNote 的任务化
  处理思路，但上线前重新核对平台条款、版权和下载限制。
- [建议] 增加来源健康状态：原文失效时仍保留已核验引用，并提示链接已经不可用。
- [建议] 不把视觉观察冒充逐字原文；OCR、画面理解、作者文案和模型推断继续
  使用不同证据类型。

### 10.4 来源笔记与长期主题

- [既定] 来源笔记忠实整理单一来源，主题笔记汇聚多个来源。
- [既定] AI 只提供可编辑初稿和局部 patch，用户确认后才成为正式内容。
- [既定] 用户不需要记住已有主题，系统负责召回候选；用户始终可以改选或新建。
- [建议] 主题支持合并、拆分、置顶、归档和别名。
- [建议] 主题主页增加时间线，查看“当前理解”如何被不同来源逐步改变。
- [建议] 新来源不仅给出“新增”，还明确标记：
  - 支持已有观点；
  - 补充新角度；
  - 与已有笔记冲突；
  - 证据不足，暂不合并。
- [建议] 冲突内容不自动抹平，保留双方来源并让用户决定如何表达。
- [建议] 用户多次修改归类或拒绝建议后，系统学习偏好，但必须提供可查看、
  可重置的规则，不能形成不可解释的隐式画像。
- [建议] 主题建立“边界说明”：它关注什么、不关注什么，减少宽泛主题吞并
  具体主题。
- [建议] 支持从主题中生成阅读清单、问题清单、下一步探索方向和待验证观点。

### 10.5 搜索、相关记忆与 Ask ReMind

- [既定] 先使用 SQLite FTS、本地规则和主题关系，再逐步加入 embedding。
- [建议] 混合检索同时考虑标题、正文、标签、主题、时间、来源和向量相似度。
- [建议] 搜索结果可按来源、内容类型、主题、时间和是否已整理筛选。
- [建议] 支持保存搜索和固定视图，例如“未整理的视频”“拉美文学最近三个月”。
- [既定] Ask ReMind 的每段回答都附笔记引用；点击回到本地笔记与来源证据。
- [建议] Ask ReMind 提供“只查某个主题”“只查指定时间”“比较两个来源”等范围。
- [建议] 对结论展示支持、反例和不确定性，不把多篇摘要拼成无来源的答案。
- [建议] 允许用户把一次问答中真正有价值的部分保存回某个主题，但仍需审核。

### 10.6 主动整理、提醒与复盘

- [既定] “最近值得再看”保持克制，每天最多一条并解释触发原因。
- [既定] 周记、月章和待办提取由用户开启，不默认制造通知压力。
- [建议] 周记包括本周新增主题、反复出现的问题、观点变化和仍未处理的收件箱。
- [建议] 月章突出长期主题的变化，而不是简单统计收藏数量。
- [建议] 待办必须能回到产生它的原笔记，并由用户确认后才进入任务清单。
- [建议] 增加“稍后提醒我”并支持自然日期，但提醒内容仍引用原笔记。
- [建议] 用户可设置哪些主题允许主动提醒、安静时间和每周上限。
- [建议] 对长期没有新增的主题给出“继续、合并或归档”建议，不自动处理。

### 10.7 首页、信息架构与视觉体验

- [既定] 保持清新、低饱和、纸卡和克制手绘感，避免“AI 驾驶舱”视觉。
- [既定] 首页默认突出最近来源，不把主题主页、原始链接和正式笔记混成重复卡片。
- [建议] 增加紧凑、标准两种卡片密度，解决内容积累后的浏览压力。
- [建议] 分类栏支持用户排序、隐藏和固定常用视图。
- [建议] 首页将“待处理任务”“最近记下”“值得再看”保持为三个明确层级，
  没有内容时自动收起。
- [建议] 主题页提供列表、时间线和来源分组视图，而不是无限增长的长正文。
- [建议] 增加批量操作和撤销反馈，主题删除、重新归类等高风险动作明确影响范围。
- [建议] 增加深色模式、动态字体、读屏标签、色彩对比和减少动画选项。
- [建议] 卡片图片只使用来源缩略预览时也不长期缓存；默认继续以文字信息为主。

### 10.8 Obsidian、导出与数据主权

- [既定] 标准 Markdown 和稳定 ID 是长期出口。
- [既定] ReMind → Obsidian 先保持单向同步，避免静默双向覆盖。
- [既定] Android 精选同步继续完善；iOS 提供 Obsidian URI 和批量导出。
- [建议] 提供 Markdown / ZIP 全量导出、增量备份和可验证恢复。
- [建议] 增加 Obsidian 插件或桌面同步器，解决 iOS 后台写入和跨平台稳定同步，
  但仍保留明确冲突策略。
- [建议] 用户可以查看每篇笔记的导出位置、最后同步时间、内容指纹和失败原因。
- [建议] 导出应包含来源关系、主题关系和证据元数据，同时保证单个 Markdown
  离开 ReMind 后仍可独立阅读。
- [建议] 增加备份健康检查和恢复演练，不能只提供“导出成功”提示。

### 10.9 成本、隐私与用户控制

- [既定] 本地 Whisper 优先，云端自动兜底；超出费用阈值先确认。
- [建议] 增加月度预算、单任务上限和模型调用明细。
- [建议] 用户可以选择“仅本地”“本地优先”“速度优先”等处理策略。
- [建议] 在提交云端前显示将发送的是正文、图片观察还是音频分片。
- [建议] 对私人内容提供不进入云端模型的标记。
- [建议] API Key 支持状态检查、轮换和撤销，不在日志或诊断页面泄露。
- [建议] 提供清晰的数据地图：手机、Mac、D1、模型服务和 Obsidian 各保存什么。
- [建议] 增加一键导出、一键删除账户数据和按来源删除处理产物。
- [建议] 日志默认脱敏，媒体临时目录和运行时密钥继续强制清理。

### 10.10 服务端、任务系统与规模化

- [既定] 媒体处理保持异步、可恢复，不阻塞微信继续收件。
- [建议] 将当前链接处理状态升级为正式 job 表，记录重试次数、阶段产物、
  租约、超时和指数退避。
- [建议] 不同用户和任务增加并发限制、配额和幂等键。
- [建议] 网关适配器增加契约测试和页面结构监控，公众号或小红书解析失效时
  能快速定位。
- [建议] 个人模式继续支持本机 Worker；面向其他用户前提供托管网关，
  不能要求每位用户都打开 Codex 或维护开发环境。
- [建议] 长任务完成、失败或等待费用确认时使用本地通知或推送。
- [建议] 服务状态、任务失败率、模型费用和适配器成功率使用脱敏指标监控。
- [建议] 正式上线前增加认证、权限隔离、限流、滥用防护和生产数据库备份。

### 10.11 发布与工程治理

- [既定] TestFlight、Google Play 内测、隐私政策和账户删除流程。
- [建议] 建立 Git 初始基线、分支规则、迁移审查和回滚说明。
- [建议] CI 覆盖 TypeScript、Worker、Gateway、Android export 和关键数据库迁移。
- [建议] 增加端到端夹具：公众号、普通网页、图文、视频和失败恢复各一套。
- [建议] 每次发布自动核对 package、图标、版本、API 地址和数据迁移。
- [建议] 增加崩溃、ANR、同步失败监控，同时允许用户关闭非必要遥测。
- [建议] 发布说明必须区分已实现、实验中和规划中，避免把个人原型描述成
  已规模化产品。

### 10.12 明确暂不做

- 不做公开社交广场或内容社区。
- 不把 AI 摘要数量、连续打卡或通知轰炸作为增长机制。
- 不默认复制和永久保存互联网上的图片、视频或音频文件。
- 不在 Expo 客户端运行 FFmpeg、Whisper、下载器或 Python 处理链。
- 不让模型在没有来源证据时替用户补出确定结论。
- 不在没有冲突策略前做静默的 Obsidian 双向同步。
- 不因为增加新模型而改变“用户审核后才进入长期笔记”的基本原则。

## 11. 不要误判为已完成

- 新版 Obsidian 重新授权与完整同步尚未确认。
- iOS Share Extension 和 Android Share Intent 尚未实现。
- 微信自助配对尚未实现。
- 当前 APK 不能自动发现变化后的 Mac IP。
- 网关尚未云化，Mac 关机或休眠时微信摄取不可用。
- 账号、跨设备同步、Ask ReMind、PDF 和播客摄取尚未实现。
- 公众号和小红书读取依赖非官方页面结构。
- 当前仓库还没有安全的正式 Git 基线提交。
