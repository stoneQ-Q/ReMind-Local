# ReMind 云端改造进度清单

> 建立日期：2026-07-29  
> 当前阶段：本地云端化  
> 详细方案：[CLOUD_ARCHITECTURE_V1.md](./CLOUD_ARCHITECTURE_V1.md)

这份文档是云端改造的持续进度记录。每完成一项，都必须同时：

1. 完成对应验证；
2. 将任务标记为 `[x]`；
3. 在“完成记录”中写明日期、结果和 Git 提交号；
4. 确认没有破坏下方列出的安全底线。

## 一、已经确定的方案

- [x] 保留“自助部署版”：沿用当前 Mac 本地方案，用户自行配置 API，只支持手机和 Mac 在同一网络。
- [x] 建设“云端托管版”：用户安装 App 后直接使用，不依赖电脑。
- [x] 云端版提供三种 AI 模式：关闭 AI、使用用户自己的 API Key、使用 ReMind 托管额度。
- [x] 用户自己的 API Key 只通过加密连接提交，由服务端加密保存，不写入日志或 App 普通数据库。
- [x] 托管 AI 使用预付费余额：先预占、后结算、失败释放，禁止负余额。
- [x] 视频等高成本任务必须显示预计费用，并设置单任务、单用户和全平台成本上限。
- [x] 私密测试首选腾讯云香港；先完成本地云端化，再购买服务器。
- [x] 腾讯云不是代码依赖：使用 Docker、标准 PostgreSQL、对象存储和密钥服务适配层，保留迁移到阿里云或大陆节点的能力。
- [x] Cloudflare 只作为当前开发环境或海外辅助，不作为国内正式版的唯一核心服务。

## 二、安全底线

以下内容在整个改造过程中都必须保留：

- `remind.db` 及其现有数据；
- App SecureStore 中的微信和设备凭据；
- Cloudflare D1 中的现有数据；
- 当前微信登录、配对和网关配置；
- Obsidian 授权及同步配置；
- 当前 1.0.2 的本地可用链路。

禁止把以下内容提交到 Git、写入日志或放进客户端安装包：

- 用户或平台的 API Key；
- 微信令牌、连接密钥和会话凭据；
- 数据库密码和云服务密钥；
- 可直接访问用户私有文件的临时地址。
