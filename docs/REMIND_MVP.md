# ReMind 移动端 MVP

> 平台：iOS / Android  
> 技术路线：Expo + React Native + TypeScript  
> 产品原则：先可靠记录，再智能整理。

## 核心体验

```text
手机随手记 → 立即离线保存 → 后台 AI 整理 → 搜索或提问找回
```

ReMind 不是把网页笔记缩到手机屏幕上。移动端首版围绕三个场景设计：

1. 临时想到一件事，打开 App 立刻输入。
2. 从其他 App 看到内容，通过系统分享进入 ReMind。
3. 之后想起模糊线索，用关键词或自然语言重新找到。

## 移动端产品结构

```text
ReMind
├── 记录
│   ├── 首屏快速输入
│   ├── 最近笔记
│   └── 笔记详情与编辑
├── 找回
│   ├── 本地全文搜索
│   └── Ask ReMind
├── 系统入口
│   ├── iOS Share Extension
│   ├── Android Share Intent
│   └── 桌面快捷入口 / Widget
└── 设置
    ├── 云同步
    ├── AI 与隐私
    └── 数据导出
```

## MVP 范围

### Slice M0：本地可用，已实现

- Expo React Native 工程，可运行在 iOS 和 Android。
- 首屏直接输入，无需先创建文件夹或选择类型。
- SQLite 离线保存，关闭 App 后内容仍在。
- 最近笔记列表。
- 标题和正文关键词搜索。
- 查看、修改和软删除笔记。
- 保存成功触觉反馈。
- 空状态、加载、失败状态。

- [x] 深链 `remind://capture` 的解析与快速记录页。
- [x] 支持从链接预填文本。
- [x] 重复入口 ID 不会创建重复笔记。

- 从浏览器分享一个网址到 ReMind 不超过三次点击。

## 本地数据模型

当前 SQLite 表：

```sql
CREATE TABLE notes (
  id TEXT PRIMARY KEY NOT NULL,
  title TEXT NOT NULL,
  content TEXT NOT NULL,
  summary TEXT,
  status TEXT NOT NULL DEFAULT 'saved',
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  deleted_at TEXT
);
```

后续 migration 增加：

- `content_hash`
- `title_source`
- `summary_source`
- `local_version`
- `server_version`
- `device_id`
- `sync_status`
- `last_sync_error`
- `tags` 与 `note_tags`
- `ai_jobs`

## 为什么使用本地优先

- 打开即写，不受网络和登录影响。
- 系统分享入口在后台唤起时仍能可靠落盘。
- 地铁、电梯和弱网环境不会丢内容。
- AI 与同步只是增强层，不成为记录的单点故障。

SQLite 是设备上的事实来源；云端承担同步、AI 任务和跨设备恢复。

## Vibe Coding 规则

1. 一轮只做一个移动端切片。
2. 每个功能必须先验证真机手势、键盘和离线状态。
3. 任何内容先本地保存，网络操作不能阻塞记录。
4. 数据结构只能通过 migration 修改。
5. 系统分享、通知、Widget 必须用 development build 真机测试。
6. 每轮结束运行 TypeScript 检查和 iOS/Android bundle 检查。
7. 涉及同步时必须测试重复提交、断网恢复和冲突。
