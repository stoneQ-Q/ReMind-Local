# ReMind 云端资源基准与首台服务器规格

日期：2026-07-30

## 一、结论

私密测试首台服务器选择：

- 腾讯云轻量应用服务器，中国香港地域，Linux；
- 中国香港入门型：2 核 CPU、4 GB 内存、70 GB SSD、30 Mbps 峰值带宽、每月 2 TB 流量；
- 当前官方刊例价为 90 元/月；首次只购买 1 个月，不做长期预付；
- PostgreSQL、API、单个 Worker 和备份容器先部署在同一台服务器；
- 用户媒体放入同地域 COS，不把长期媒体文件堆在 70 GB 系统盘；
- 视频 Worker 并发固定为 1，只有队列和监控证明需要时才升级。

本机实测表明，ReMind 的常驻内存、账号、计费、任务编排和大文件分片都很轻。视频音频提取主要消耗 CPU，但单任务执行时间短、内存峰值低。2 核 4 GB 足以作为少量私密测试用户的最低成本起点；2 核 2 GB 虽可能运行，但留给 Docker、PostgreSQL、系统缓存、备份和突发任务的余量太小，不采用。

不选择 2 核 4 GB 锐驰型作为默认方案：其 200 Mbps 是共享资源下的峰值而非承诺指标，腾讯云说明高峰期可能受资源争抢影响，而且锐驰型不能开启面向中国大陆访问的优选流量包，后续也只能在锐驰型内部升级。ReMind 的首要目标是验证大陆三网稳定性，而不是追求瞬时大带宽。

## 二、测试边界

测试环境：

- 主机：Apple M5，10 核，32 GB 内存；
- Docker Desktop：10 核，7.75 GiB 内存上限；
- 服务：API、PostgreSQL 17、Worker、备份容器；
- 媒体供应商：`disabled`；
- 测试数据库和对象目录全部隔离并在结束后清理；
- 未请求真实智谱、DeepSeek 或其他外部模型，未产生模型费用；
- 未改变主开发数据库、App 数据、微信配置或 Obsidian 授权。

本机 SSD 和回环网络明显快于云服务器，因此本地吞吐量只用于发现 CPU、内存和实现层面的瓶颈，不能当作腾讯云公网速度承诺。跨境网络必须在服务器开通后用移动、联通、电信分别实测。

## 三、实测结果

| 场景 | 结果 | 观察 |
| --- | --- | --- |
| 空载常驻 | 四个容器合计约 107 MiB | API 约 28.5 MiB、Worker 约 30 MiB、PostgreSQL 约 47.7 MiB、备份约 0.8 MiB |
| 完整功能链 | 2.69 秒；测试进程最大 RSS 约 98 MiB | 依次覆盖迁移、账号、计费、任务、微信、链接、对象、上传和媒体编排 |
| 4 组完整功能链并发 | 3.27 秒；PostgreSQL 观察峰值约 76 MiB | CPU 和数据库仍有明显余量；每组测试进程最大 RSS 约 100 MiB |
| 256 MB 分片上传 | 64 个 4 MB 分片，0.61 秒；约 421 MB/s；最大 RSS 约 137 MiB | 完成 SHA-256 校验和原子发布；速度是本机磁盘结果，不代表公网 |
| 1 小时 1080p 视频 | 4.55 秒；Worker 峰值约 66 MiB；约 9.38 CPU 核秒 | 生成 129 个 28 秒音频片段，共 14.1 MiB |
| 4 个 1 小时视频并发 | 7.44 秒；Worker 峰值约 187 MiB；约 48.8 CPU 核秒 | 在 10 核环境平均占用约 6.6 核，证明并发主要受 CPU 限制 |
| 256 MB 对象写入与校验 | 0.89 秒；容器峰值约 290 MiB | 峰值包含 Linux 文件页缓存，仍远低于 4 GB |

大文件基准可以重复执行：

```sh
REMIND_RESOURCE_UPLOAD_MB=256 npm --prefix cloud run smoke:billing
```

环境变量仅在显式设置时增加资源测试；普通冒烟测试行为不变。允许范围是 1 MB 至 1024 MB。

## 四、部署限制

首台 2 核 4 GB 服务器采用以下限制：

- 视频 Worker 并发：1；
- API 内存目标上限：256 MiB；
- Worker 内存目标上限：1 GiB；
- PostgreSQL 内存预算：512 MiB；
- 操作系统、Docker、备份、日志和文件页缓存保留至少 1.5 GiB；
- 系统盘只保存系统、镜像、数据库、短期缓存和短期备份；
- 用户源媒体、分片和处理结果进入同地域 COS；
- 临时媒体处理成功或失败后都必须清理；
- 保持至少 20 GB 系统盘可用空间。

## 五、升级条件

出现任一条件时，从 2 核 4 GB 升级或拆分 Worker：

- CPU 连续 15 分钟超过 70%；
- 视频任务最老等待时间超过 5 分钟，或持续排队超过 3 个；
- 内存连续 15 分钟超过 80%，或出现交换分区活动；
- 系统盘使用率达到 70%；
- PostgreSQL 慢查询或连接等待连续出现；
- 三网测试确认网络质量需要更高等级线路，而不是单纯增加计算资源。

优先升级顺序：

1. 保持 Worker 并发为 1，先确认是否为供应商限流或网络问题；
2. 计算资源不足时升级到 4 核 8 GB，或把 Worker 单独拆到第二台实例；
3. 数据库规模和用户量继续增长后，再迁移到独立 PostgreSQL；
4. 所有迁移继续使用 Docker、标准 PostgreSQL 和对象存储接口，不绑定腾讯云专有业务逻辑。

## 六、购买前说明

腾讯云当前明确提示，中国香港入门型套餐不保证中国内地跨境公网质量，可能出现延迟和丢包。因此：

- 首次只按月购买，先完成 7 至 14 天三网真机测试；
- 购买后立即测试普通线路；
- 如果普通线路不稳定，评估优选流量包或 CVM 优质线路，而不是让测试用户承担体验问题；
- 测试结果未达标时不邀请用户，也不因为已经购买服务器而继续投入。
