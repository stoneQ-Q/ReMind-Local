## 3. 当前产品定位与原则

ReMind 是移动端优先、本地优先的个人记忆与知识整理 App。核心不是批量制造 AI
摘要，而是：

```text
低压力记录
  → 保留原始来源和用户意图
  → AI 基于证据整理
  → 用户可选择审核、自动生成或自动归类
  → 形成长期主题、找回、问答和周期回望
```

继续遵守：

- 先保存，再理解；网络或 AI 失败不能导致原始记录丢失；
- 模型结论必须能回到用户记录、网页证据或视频时间戳；
- 找不到依据时明确说不足，不用通用知识补成确定答案；
- 自动化是用户选项，主题分类之后仍可修改；
- “最近值得再看”宁可不显示，也不展示牵强关联；
- 不把 OCR、画面识别或人格／心理诊断偷偷加入普通图片记录和周期洞察；
- 媒体下载、FFmpeg、Whisper 和 Python 处理继续留在服务器，不进入 Expo 客户端。

## 5. 必须准确说明的数据边界

当前“云端模式”不等于完整多设备笔记同步：

- 旧荣耀手机的历史 SQLite 笔记不会自动出现在新 Redmi；这是当前设计边界，不是恢复失败；
- 云端目前主要同步同账号新进入微信的捕获记录；
- 手机生成的整理笔记、主题修改和普通随手记仍主要保存在本机数据库；
- 图片原文件只存在创建它的手机，不上传云端，也不进入当前 JSON 备份；
- 删除图片笔记会在当前设备回收文件，但跨设备删除传播尚不存在；
- 用户 API Key 已加密保存，不能打印、写入文档、提交 Git 或暴露在诊断日志中；
- 托管 AI、托管媒体收费和面向公众的计费仍未开启。

## 6. 用户接下来几天的使用观察重点

这几天优先真实使用，不急着继续堆功能。下次先询问并记录具体例子：

1. 首页是否仍显得拥挤，最近 3 条和今天概览是否足够；
2. “笔记”页三类内容是否容易理解，是否仍有“一进去看到太多条目”的压力；
3. 自动整理模式是否产生错误笔记、重复笔记或错误主题；
4. 自动主题分类是否容易改回正确主题；
5. “最近值得再看”是否真的相关；没有推荐是否比牵强推荐更舒服；
6. 问 ReMind 的回答是否找得到真正想找的内容，引用是否足够直接；
7. 图片加感想的版式是否自然，1 张、2 张和 4 张的实际效果是否都满意；
8. 微信文字、公众号和视频是否能稳定进入，处理耗时是否可以接受；
9. 服务器 Whisper 排队时是否明显变慢，是否出现任务长时间无反馈；
10. 电量、网络切换、冷启动、后台恢复和连续使用是否出现闪退或状态丢失。

收集问题时保留“具体记录／具体页面／发生时间／期望结果”，不要只按抽象描述立刻改 UI。

## 7. 后续优化方向与优先级
