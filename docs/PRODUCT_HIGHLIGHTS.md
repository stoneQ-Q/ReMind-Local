# ReMind 产品亮点与自媒体发布稿

> 文档用途：阶段性产品介绍、自媒体图文、演示视频口播和项目复盘。  
> 当前阶段：个人可用原型，Android 真机闭环已跑通，尚未公开规模化发布。

## 一句话介绍

ReMind 是一个会把文章、图文和视频“长进你的笔记里”的个人知识 App：
先从微信低压力收下内容，再生成可审核、可追溯的来源笔记，并持续补充用户
自己的长期主题。

## 核心表达

> ReMind 不只是总结内容，而是让知识长进你的笔记里。

> 每一次投入，都让已有笔记变得更完整，而不是让摘要列表变得更长。

## 长文发布稿

### 我为什么做 ReMind

我一直有一个很具体的困扰：

看到一篇好文章、一个小红书视频或者一段值得留下的话时，我会先收藏，
或者把链接发给自己。但过几天以后，我往往只记得“好像看过”，已经不记得
当时为什么想留下，也不知道它和过去读过的内容有什么关系。

很多 AI 笔记产品解决的是“帮你总结一篇内容”，但总结完成后，常常只是
收藏夹里又多了一张摘要卡片。卡片越来越多，知识却没有真正沉淀下来。

所以我做了 ReMind。

### 它现在是怎么工作的

我可以直接把文字、微信公众号文章或者小红书链接发给微信，不需要先打开
笔记 App，也不用立刻想清楚该放进哪个文件夹。

ReMind 会先把原始内容可靠收下。然后再去读取文章、识别图文，或者转写
视频中的语音，生成一篇可以审核的笔记。

它不会直接替我做决定。我可以修改标题和正文，核对引用的原文，再决定是否
接受。AI 生成的是初稿，最后留下来的仍然是我自己的普通 Markdown 笔记。

### 我最在意的是“来源可追溯”

整理文章时，ReMind 不让模型凭印象复制原文。系统会先把正文切成稳定的证据块，
模型只能选择证据编号，之后再由程序取回逐字原文。

所以一条观点不仅有概括，还有它来自哪一段、原文是什么、原始链接在哪里。
对于视频，转写结果会带时间位置；需要核对时，可以回到原视频上下文。

这并不能保证 AI 永远正确，但至少让错误更容易被发现，也让一篇笔记离开 App
以后仍然能够被理解和复核。

### 它不会要求我记住过去有哪些主题

真正让我觉得有意思的，是“持续生长的主题笔记”。

例如我先保存了一篇拉美文学作品推荐，之后又保存了一篇《百年孤独》的阅读理解。
ReMind 会评估它们是否应该进入同一个长期主题，而不是要求我先想起以前建过什么
文件夹。

如果匹配合理，它会建议把这次的新内容补充进去；如果不合理，就建议新建主题。
我可以手动改选主题，也可以自己输入名称。

每篇来源仍然独立保留，但主题主页会逐渐形成一份“当前理解”，下面能看到每篇
来源贡献了什么、何时加入、原文在哪里。新的内容只提供局部更新建议，不会每次
把整篇长期笔记重写一遍。

### 视频处理也尽量克制

ReMind 目前已经能处理小红书视频链接，但它不会默认把整段视频交给视觉模型。

系统先临时提取音轨，优先用我电脑上的 Whisper 转写；本地不可用时，才使用云端
语音识别。云端费用超过设定上限时，会先停下来等我确认。

转写完成后，临时视频和音频会被删除。App、数据库和 Obsidian 只保存提炼后的
文字、必要的时间位置和原始链接。

我更希望它保存“以后还用得上的理解”，而不是复制一份互联网上本来就存在的
媒体文件。

### 它也会把旧内容找回来

在一篇来源笔记下面，ReMind 会列出过去的相关内容，并说明为什么相关。

首页每天最多出现一条“最近值得再看”，用最近保存的内容唤起一条更早的笔记。
打开过的内容不会立刻反复出现，选择暂时不看以后也会安静一段时间。

我不想再造一个无限刷新的信息流。真正有价值的是：在恰当的时候，让已经属于
自己的知识重新出现。

### 为什么最后还要进 Obsidian

ReMind 负责低压力捕获、整理和找回；Obsidian 负责长期保管、链接和深度编辑。

确认后的笔记可以写入 Obsidian Vault，使用普通 Markdown、稳定 ID 和原始链接。
即使以后不再使用 ReMind，这些文件仍然可以独立阅读。

我不希望个人知识被困在一个只能由某个 App 打开的黑盒里。

### 现在做到哪一步了

目前 Android 真机已经跑通：

```text
微信捕获
→ 网页、图文或视频处理
→ 可审核来源笔记
→ 长期主题
→ 相关记忆
→ Obsidian
```

它已经可以脱离 Codex 和 Expo Go 独立运行，但目前仍然依赖同一局域网里的一台
Mac 承担微信网关、本地 Whisper 和 Worker，因此还是一个个人原型，不是可以
直接服务大量用户的正式产品。

下一步我会继续补上 App 内微信自助配对、Android/iOS 系统分享、稳定的网关发现、
更多真机回归，以及播客、PDF 和 Ask ReMind。

ReMind 想解决的并不是“怎样更快地产生摘要”，而是：

> 怎样让今天看到的内容，在未来真的成为自己能够继续使用的理解。

## 短版发布文案

我做了一个叫 ReMind 的个人知识 App。

把微信公众号文章、小红书图文或视频发给微信，它会先保存原始内容，再生成一篇
可审核的来源笔记。观点能够回到原文证据，视频转写保留时间位置。

更重要的是，新内容不会只变成又一张摘要卡片。ReMind 会尝试找到相关的长期主题，
建议局部补充，并把每篇来源的贡献独立保留下来。用户不需要记住过去建过哪些主题，
也可以随时修改分类和正文。

它还会从最近的内容出发，找回一条过去的相关记忆；确认后的笔记则以普通 Markdown
进入 Obsidian。

我希望它做到的是：

> 每一次投入，都让已有笔记变得更完整，而不是让摘要列表变得更长。

目前 Android 真机闭环已经跑通，仍处于个人原型阶段。

## 适合短视频的 60 秒口播

我最近做了一个叫 ReMind 的笔记 App。

平时看到文章或小红书视频，我不需要先打开 App，只要把链接发给微信。它会先把
原始内容收下，再读取文章、识别图片或者转写视频，生成一篇可以自己修改和审核的
笔记。

我最在意的不是摘要，而是来源。每个观点都能回到对应的原文，视频内容也保留时间
位置。

当我以后再保存相近内容时，ReMind 会主动想起过去的主题，建议把新知识补进去，
而不是让我记住以前建过什么文件夹。每篇来源仍然独立保留，主题则慢慢形成自己的
“当前理解”。

确认后的笔记还可以直接进入 Obsidian，保持普通 Markdown 格式。

它现在已经在 Android 手机上跑通了完整闭环。我的目标不是做一个更快的摘要工具，
而是让每次收藏都真的长进自己的笔记里。

## 建议配图与演示顺序

1. 首页：快速记录框、低饱和纸卡和最近内容。
2. 微信：发送“链接 + 为什么想保存”。
3. 处理卡：视频转写阶段、分段进度和费用确认。
4. 审核页：整理结果与原文证据并排出现。
5. 主题主页：“当前理解”与多篇来源卡片。
6. 相关记忆：展示关联原因，而不只显示“猜你喜欢”。
7. Obsidian：同一笔记的 Markdown、稳定 ID 和原始链接。
8. 架构简图：微信 → 网关 → Worker → App → Obsidian。

演示时应使用虚构或已获授权的内容，遮盖微信头像、设备标识、配对码、
API 地址和私人笔记。

## 发布时必须保留的事实边界

- 可以说“Android 真机闭环已跑通”，不要说“已经正式上线”。
- 可以说“独立安装后不依赖 Codex”，同时说明当前仍依赖个人 Mac 和局域网。
- 可以说“模型观点可回到程序校验的原文证据”，不要说“AI 绝不会出错”。
- 可以说“本地 Whisper 优先，云端自动兜底”，不要说“所有处理都完全本地”。
- 可以说“不长期保存来源图片、视频和音频”，不要暗示原始网页永远可访问。
- 小红书和公众号读取依赖页面结构，公开演示前应重新验证平台适配情况。
